# 建筑与模块搬移

TF3 本地开发版，Mod ID：`xiaom_building_mover`，修订 7 候选版。本机 Build `25533170`。46 项开发检查通过。修订 6 已实测免费搬移及存档重载；本次新增的原版吸附、按键与按钮调整尚待游戏内验收，暂不作为验证完成的发布版。

## 操作

打开建筑详情，点击“配置”右侧的“移动”，直接进入地图放置预览。

- 建筑连同所有子模块跟随鼠标；原配置、随机种子、模块变体和所有权一起保留。
- 左键放置；右键或原版返回键取消。取消和无效位置不提交任何建筑修改，原建筑保留。
- 使用玩家设置的建造旋转、升降按键；精细模式可微调。保留建筑原有方向、倾斜、缩放及相对地面的高度，再叠加本次调整。
- 按键由原版 `ConstructionAction` 处理。默认 M/N 旋转、句号/逗号升降，Shift 为精细模式；实际采用游戏中的按键映射。提示窗口也提供旋转 ±15°、升高、降低按钮，显示当前角度和高度。
- 每次进入搬移模式只移动一栋建筑，放置成功后退出，连续点击不会产生复制品。
- 整栋和单个模块搬移均不指定玩家付款账户，建筑所有权由更新提案保留。无需先拆除，不产生拆除退款，不改变普通新建建筑的费用规则。

在搬移提示窗口点击“移动单个模块”，选择已建模块和同类空插槽，再预览和确认。只能在同一建筑内部换槽；占用、不同类型和导致其他模块丢失的方案会被拒绝。“移动整栋建筑”返回地图放置。

## 更新与安装

本机 `staging_area` 目录联接指向 `F:\mod\Transport Fever 3\staging_area`，源文件修改已同步到游戏开发目录，无需复制。重新载入启用了本 Mod 的测试存档副本以加载修订 7 候选版；当前游戏尚停留在主菜单，桌面输入接口故障阻塞了此次实机验收。

其他机器把完整 `xiaom_building_mover` 文件夹复制到 `E:\steam\steamapps\common\Transport Fever 3\mods\release\`，然后在新游戏或载入存档的 Mod 设置中启用“建筑与模块搬移”。从修订 1 更新时完整替换文件夹，避免残留旧 `building_mover.gs.lua`。

修订 3 修复 Recipe 布局注册；修订 4 改成鼠标放置，并使用本机原版实际调用的矩阵实例方法。修订 5 修复跨回调访问临时原生预览对象：预览回调内完成检查，随后只提交 Mod 自己持有的 SimpleProposal。修订 6 修复完成回调将数字实体 ID 当成表读取导致的闪退，兼容实际返回值与类型声明中的二元组；同时修正付款上下文，实测整栋及模块搬移均不扣款。旧版仅设置 `playerInitiated=false` 仍会扣款。

## 接口与范围

修订 7 使用原版 `ConstructionBuilder` 计算道路吸附后的位置与方向，再以原建筑参数及全部模块生成带旧→新映射的免费更新。原版建造器自身的新建提交被禁用，搬移工具单独校验并提交更新。吸附结果仅在原生回调内复制矩阵，不保存借用的原生提案。**实际道路网络是否自动连接、左键事件是否正确路由仍待实机验收**，不能将模拟中的吸附位置检查等同于道路连通验证。

当前 API 修改建筑需要一次带 `old2new` 映射的更新提案。Mod 提交一次原子更新，保留关联映射和全部模块，不执行“先拆除、再另建”的两步操作；实体 ID 仍可能变化。实测金华仓库的鱼及原油库存保留，港口入口换槽后的三条原线路仍显示，搬移后存档能够重载。其他建筑状态和第三方 Mod 保存的实体 ID 仍需分别验证。

面向具有 `CONSTRUCTION` 组件的建筑。独立道路、轨道、信号及建筑外部的接入道路不会整体随建筑搬移，放置后需检查连接。地形与碰撞仍遵循游戏规则，其他建筑或其他建筑的子模块不会被自动拆除。
